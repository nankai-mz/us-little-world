# 实现架构

## 三个运行面，共享业务核心

- `src/core`：端到端加密、密钥库、日期、宠物、胶囊、统计和业务服务。
- `src/server/api.ts`：框架无关的授权与事务处理。不会接收日记正文或明文空间密钥；AI 单次授权接口除外。
- `src/server/cloud-entry.ts`：真实 CloudBase 文档数据库 / 云存储适配器。身份只取 `cloud.getWXContext().OPENID`，不采用客户端传入的身份。
- `miniprogram`：六个原生路由（五个 Tab + 共用工作页），用 `screen` 区分编辑、详情、安全等二级页面。所有 Tab 共享唯一 `platform.js` 会话实例。
- `web`：React / Vite 浏览器预览，采用同一个 API 处理器和业务服务，数据库适配器改为本机加密持久化。没有模拟跨微信同步。

原设计的多组路由被收敛为共用工作页，避免重复打包密码库；产品入口与主导航仍保留。宠物、胶囊等内容通过统一 `encrypted_records` 存储，类型在密文内，不再分别建可泄露类型的集合。

## 密钥和记录

1. 系统安全随机源生成 256 位个人主密钥、共享空间密钥和设备种子。微信端仅使用 `wx.getRandomValues`，无不安全随机数回退。
2. 设备有 X25519 加密密钥和 Ed25519 签名密钥，二者共同参与安全码计算。
3. 用 HKDF-SHA256 为每个记录上下文派生密钥。AEAD AAD 绑定空间、记录、作者、可见范围、模式版本和密钥版本；内容使用 192 位随机 nonce 的 XChaCha20-Poly1305。
4. 个人记录使用个人主密钥。共同记录使用当前版本共享密钥。记录类型、标题、日期、标签、心情、坐标都在密文内。
5. 本机密钥库整体以口令派生密钥（scrypt）加密，并另用随机恢复密钥包装。恢复密钥保存在加密密钥库内，以便后续密钥更新后重新生成恢复包。服务端不保存恢复明文。
6. 分享密钥前，输入已经通过可信渠道核对的安全码。发送方使用临时 X25519 密钥协商、加密空间密钥并用 Ed25519 签名。签名使用固定字段顺序的数组编码，不依赖数据库对象键顺序。
7. 轮换时只向本机已验证的活跃设备分发新密钥。云端用事务比较旧密钥版本，记录随机密钥的 SHA256 承诺，客户端借此排除并发失败时产生的错误同版本密钥。云端无法从承诺计算随机密钥。

## 文件

图片先在设备缩放 / 压缩，再读取字节加密；名字、实际 MIME、大小、关联文件标识在记录密文内。云函数负责转存 / 取回密文，普通客户端不直接读写数据库或存储。不生成公开永久图片链接。

采用小图片整体加密，新上传图片限制为 500 × 1024 字节。共享 `photos.ts` 按实际输出字节决定是否继续降质 / 缩放，最多八次，从原始图重新编码，不按文件扩展名猜 MIME；输入上限 25 MB。网页使用 Canvas，微信使用 `wx.compressImage`。不批量改写历史照片，暂不支持大视频分块协议。压缩临时文件在处理结束后清理，原始选择文件保留。微信解密图片会临时写入应用目录用于 `image` 展示，在隐藏、页面退出、锁定与重新启动时清理；这不提供操作系统级安全擦除保证。

## 权限与并发

- 成员和设备检查在 API 层执行，重要写操作在事务内重新检查。空间成员上限和邀请使用在同一个事务内完成。
- 所有修改比较 revision；冲突明确报错，不静默覆盖。宠物与双人答案仅在明确 revision 冲突时读取最新状态后有界重试；网络失败或结果未知的写入不自动重发。
- 私人记录在服务端过滤；不向另一位成员返回其密文。已获共享密钥也不能打开个人密钥加密的记录。
- 回收站是加密记录的逻辑删除。永久删除仅限作者自己的回收站记录；照片同步清理失败时可能残留不可通过应用展示的密文文件，应由维护流程核对。
- 空间关闭保留历史服务器密文但拒绝双方后续请求，当前版不提供重开流程。应先导出；关闭后服务端管理员也不能恢复客户端遗失的密钥。
- 空间成员关系、设备公钥、密文大小、访问时间和必要授权元数据仍可被服务器看到。
- 刷新以会话和请求序号隔离，合并其间完成的写入；锁定会失效等待中的刷新和界面缓存更新。本机数据库持久化成功后才提交内存状态。
- 原生网络适配器为请求设置超时；只读接口最多重试一次，写入与 AI 不自动重发。`health` 仅返回运行状态，不检查或证明实际云端权限规则。

## AI 与外部服务

客户端只从共同日记中选择文字。请求前显示完整预览、取消旧授权、单次确认；服务器只在短期有效授权和限流通过后调用配置的模型服务。输入正文和模型结果不进入应用日志或数据库。服务商自身的处理 / 保留规则需由部署者告知使用者。

外部地图只有用户主动调用时才接收坐标；文字地点可以始终不提供坐标。没有后台定位、在线状态、阅读追踪、第三方分析和远程字体。

## 题库与展示层

`src/core/questions.ts` 是两端共用的 120 题 / 24 道默契题分类库。每日轮换按连续日期序号计算，不在每月一日重置。历史记录沿用空间、类型、日期和标题的既有 ID 规则，续答使用历史日期；自定义提问存为共同加密记录，不发送到外部服务。数据格式和 API 协议版本保持不变。

原生展示层单独生成 `coverPhotoUrl` 与照片 `url`，不把本机解密路径写回加密记录；示例插画在构建时转成 PNG。`scripts/wxml-check.mjs` 检查条件绑定、列表绑定与标签闭合，并由原生检查绑定事件和标题导航。此检查没有运行微信 WXML 编译器。

## 已知技术界限

日期胶囊和双人答案揭晓属于业务规则，持有共享密钥的用户可在应用外查看密文内容。小程序运行时、浏览器、设备被攻破或恶意代码更新均可能读取解锁中的明文。本版没有声称抵抗上述攻击，也没有独立密码学审计。
