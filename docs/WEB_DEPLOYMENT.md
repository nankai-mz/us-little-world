# Us Web 部署与恢复

发布包包含应用、静态资源、快照工具和 Linux 主机配置示例。使用支持 `node:sqlite` 且经本项目验证的 Node.js 24。应用和反向代理部署在同一台主机。数据库路径指向独立持久存储，应用目录用于发布版本切换。

## 预发布

1. 在源码目录运行 `npm ci`、`npm run check:web` 与浏览器端到端检查，然后运行 `npm run package:web`。发布包和同名 `.sha256` 文件出现在 `artifacts/web-release/`。用 `sha256sum -c` 校验 ZIP。包内 `manifest.json` 包含每个组件的 SHA-256 供部署后核对。
2. 将 ZIP 解压到该版本的发布目录。Linux 示例约定 `/opt/us-web/current` 指向已解压版本，`us-web` 是服务账户，`/var/lib/us-web` 由服务独占。按实际 Node 路径调整 `deploy/web/us-web.service`。也可在解压目录直接运行 `node server.mjs`，由服务管理器注入环境变量。
3. 将 `deploy/web/web.env.example` 作为 `/etc/us-web.env` 的模板，配置稳定的账号名、两个独立随机密码、对应入口的 `US_WEB_ORIGIN` 和持久卷上的 `US_WEB_DB`。限制环境文件读取。HTTP 回环服务监听 `US_WEB_PORT`，反向代理与应用保持相同端口配置。
4. 用 `deploy/web/Caddyfile` 配置专用域名和到回环服务的转发。配置 DNS、证书和外部访问后检查证书有效期、HTTP 跳转、`GET /healthz` 及 Cookie 的 `Secure`、`HttpOnly` 和 `SameSite=Strict` 属性。测试环境使用不同的域名、账号和数据库。
5. 用两部实际手机、不同账号核对配对、安全码、照片同步、私人记录、换机、断网重放和导出。记录构建版本、设备、浏览器和结果。开发机隔离 HTTPS 测试使用一次性证书，正式环境另行验证证书链、续期和域名。
6. 发布后刷新浏览器取得当前客户端。网站进程重启后需要重新登录并解锁。已有完整授权的旧设备在解锁时会登记个人恢复公钥。使用这类旧设备核对备份和恢复密钥后，再验收首次换机。试验环境可验证 60 秒设备挑战与 120 秒高风险操作许可的过期行为。
7. PWA 的网站清单、Service Worker 和公共离线页均由同源应用提供。让两位成员分别从实际手机的浏览器安装或添加到主屏幕。在「我的」开启本机密文缓存并联机同步后，断网重开，用本机口令核对日记和已缓存照片。在持有当前空间密钥且最近一次联机访问时空间可写的设备上，可新建或编辑日记、添加照片并保存到待同步队列。联网后从「我的 → 连接与同步」发送，核对账号、设备和内容可见范围。

在解压的候选包中执行 `node scripts/check-web-origin.mjs https://us.example.com`，将示例域名替换为实际 HTTPS 源。命令使用 Node 信任的证书链，无需网站账号，检查健康、HSTS、匿名会话、安装清单、Service Worker 和已部署静态资源的 SHA-256。保留命令的 JSON 输出作为冒烟记录。实际账号的 Cookie、HTTP 跳转和真机流程继续按上述步骤核验。

## 备份和恢复演练

Linux 发布包附带 `us-web-backup.service` 和 `us-web-backup.timer`。配置 `US_WEB_BACKUP_DIR` 后，在预发布机先运行一次服务并检查快照和日志，再启用每日定时器。默认状态目录是 `/var/lib/us-web-backups`。数据或备份目录使用自定义卷时，按实际路径配置服务的目录权限。确认备份卷可创建硬链接。

服务依次执行 `node scripts/maintain-web.mjs backup` 和 `node scripts/maintain-web.mjs check`。检查以 JSON 报告最近一份快照的年龄及数据、备份两卷的可用空间比例。超过 24 小时无快照或任何一卷剩余空间低于 25% 时返回退出码 1。将此状态和站点的 `/healthz` 接入目标环境的告警。按约定将副本保存到异地并执行保留策略，再独立验证最近副本可恢复。

在解压发布包的根目录执行。目标快照和恢复候选目录须已创建，目标文件为新路径且文件系统支持硬链接。

```sh
node scripts/backup-web.mjs /var/lib/us-web/us.sqlite /srv/backups/us-20261117.sqlite
node scripts/recover-web.mjs /srv/backups/us-20261117.sqlite /srv/recovery/authoritative.sqlite /srv/recovery/candidate.sqlite
```

- 快照包含服务器持有的加密照片、密文记录和授权元数据。两位成员分别离线保存自己的加密恢复信封和恢复密钥。ZIP 图文归档是独立的明文导出。
- 恢复前停止业务写入。参考库须来自同一数据库、包含最新已确认的撤销和删除状态。恢复工具核对数据库沿袭与版本序号，生成新文件并列出消除的记录、照片和授权。成员或空间密钥版本变化时使用兼容的较新备份。无法取得可信参考库时，只在隔离环境查看并人工核对旧快照。
- 核对议定恢复点之后的写入差异。候选保留来自快照的可恢复内容，快照之后的修改和新增内容可能需要单独迁移。失效设备继续拒绝访问，一次性邀请码与待接收密钥包需要重新发送。个人恢复公钥和加密昵称以较新的同源参考库为准。让两人验证候选的共同记录、私人记录、照片、撤销状态与回收站后才切换 `US_WEB_DB`。
- 发布异常时停写、保留当前库快照与旧发布目录。新版本启用数据库 schema 2。回退前先验证二进制与目标数据库版本兼容。需要恢复数据库时，将通过核对的候选置于新的持久文件路径，保留原文件供回退和复核。
- 增量游标有效期为七天，并在网站进程重启后失效。浏览器会重新核对成员和设备并分页重建快照。恢复候选重置派生的同步记录，恢复后首次同步以候选库中的密文记录为准。
- 网页中「先存本机，稍后同步」的日记和新增照片仍在该浏览器的 IndexedDB。同步先确认照片回执，再提交带原修订号的日记。备份服务器数据库前，请在「我的 → 连接与同步」检查队列。清除站点数据会移除本机队列。发送时需要有效的解锁与网站会话，以及支持 Web Locks 的浏览器。
- Service Worker 只缓存公共页面壳、清单和打包资源。离线日记每次要求本机解锁，读取最近 24 小时内的 IndexedDB 密文快照和此前联机查看后缓存的照片。单账号最多缓存 16 MiB 照片密文，空间不足时优先移除较旧的照片。关闭密文缓存开关会清除快照与照片缓存。网络恢复时，正在编辑的页面会提示先保存。新版本准备完毕后可在「我的」更新，操作前先处理正在编辑的内容。
