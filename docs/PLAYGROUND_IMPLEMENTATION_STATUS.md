# 双人游戏与共创系统

实施基线为 Web 分支 `3aff524`。范围、阶段和验收条目见 [完整开发计划书](US_TWO_PERSON_PLAY_AND_CREATION_ROADMAP.md)。原有日记、相册、配对、设备授权和银河继续使用同一份数据。

## 在独立环境打开

使用两组测试账号和独立 SQLite 路径。对外源需要 HTTPS，浏览器通过同源 WSS 连接实时房间。附带的测试会自行生成账号、证书和临时数据库。

```powershell
npm run test:play:unit
npm run test:play:integration
npm run test:play:e2e
npm run test:play:perf
```

在独立预发布站点的环境配置中设置 `US_WEB_PLAYGROUND=playground,async_games,shared_canvas,realtime_games,creative_worlds`，从「一起做」进入。配置留空时沿用原入口。逐步放开时先启用 `playground,async_games`，再按需要加入后续模块。实时模式依赖 `shared_canvas`。房间链接仍要求网站登录、配对和设备解锁。公开发布前见 [部署、备份与恢复](WEB_DEPLOYMENT.md)。

## 关卡维护

密室、星际探险和光影迷宫从 `src/features/scene-core/level-campaign.json` 读取关卡。在源代码工作区运行工具，序号从 1 开始。工具与运行时采用同一套结构校验。提交新版前复核旧房间会重放到的关卡坐标、机关顺序和答案。

```powershell
npm run scene:levels -- list g13
npm run scene:levels -- validate
npm run scene:levels -- export g13 1 shadow-draft.json
# 编辑 shadow-draft.json 后校验和应用
npm run scene:levels -- check g13 1 shadow-draft.json
npm run scene:levels -- replace g13 1 shadow-draft.json
npm run test:play:unit
```

`replace` 在整份配置通过校验后替换开发工作区的源文件。最后一条命令逐关用游戏规则重放已配置的双人路线。

## 同步、加密与持久化

| 入口 | 实现 |
| --- | --- |
| 网页路由与编辑器 | `web/routes.ts`、`web/features/playground/` |
| 活动协议与回放 | `src/features/play-core/` |
| 画布、拼图与关卡 | `src/features/canvas-core/`、`src/features/puzzle-core/`、`src/features/scene-core/` |
| 房间、权限与生命周期 | `src/server/activities/`、`src/server/realtime/` |
| 作品与保留 | `src/server/works/`、`src/server/migrations/playground.ts` |
| 浏览器与隔离恢复测试 | `e2e/playground.e2e.ts`、`tests/playground-*.test.ts` |

- `POST /api/space` 沿用同站 Origin、网站会话和签名登记后的设备绑定。`play.*` 管理房间、回合和检查点。`works.*` 管理私人或共同作品及版本。每次请求在数据库访问点重新核验配对关系和设备状态。
- 房间操作包括 `play.createRoom`、`play.joinRoom`、`play.getRoom`、`play.listRooms`、`play.submitTurn`、暂停、续局、续期和错峰切换。结束及收藏分别以当前操作序号核对双方确认。检查点以 `play.putSnapshot` 和 `play.confirmSnapshot` 提交及确认。
- `/ws/play?room={id}` 要求同源 Cookie 和一次性 Ed25519 设备签名。只在当前房间显示临时在场状态。正式操作落库后返回 ACK；浏览器从 SQLite 事务序号补读。实时笔迹预览仅转发加密数据，离场或超时后移除。
- 画布可开启搭档光标。标记取自当前分镜加密笔迹预览的末端，只在绘制手势中同步。光标随预览消失，不写入进度或导出。
- HKDF-SHA256 用活动 ID 的小写十六进制文本作为 UTF-8 salt，info 为 UTF-8 字符串 `Us/play/v1`。加密复用原 XChaCha20-Poly1305 封装和独立随机 nonce。AAD 绑定空间、资源、操作、设备、密钥版本及对应协议字段。服务端索引保存模式、活动批次、房间状态、顺序和大小等元数据。
- 客户端只把密文写入待确认队列和本机草稿。五子棋在服务端原子核对回合人；匿名答案、章节和场景规则在客户端独立重放。冲突默认要求重新核对，独立操作只会在原回合重试。两位成员确认同一个检查点后才压缩较早操作；旧操作回执仍能确认。
- 可重试的网络故障和同回合并发冲突会在页面可见时继续尝试。进度已越过原回合或物件版本不符时，仍需核对或放弃待确认操作。画布离线笔迹在本设备按顺序补发，确认一致前保留待同步提示。
- G03 和 G09 的揭晓属于界面规则。G06、G07、G01 和 G10 的谜底另用出题者个人或设备密钥保护，要等出题者揭晓。仅共享设备创建的谜底要在原设备上解封。密室的线索视图依角色展示。
- G01 默认用公共词库，共同回忆由画者主动切换选择。橡皮拖过的整笔作为一次加密操作同步，可一次撤销。猜中或超时后，由能解封题目的画者设备自动提交结果。画者离开时等待其回房，进行中或待同步的笔迹先保留，再生成结果画作。
- SQLite 从 v2 增量升级至 v3。房间、操作、回执、检查点、作品版本和作品媒体关系写入原 `documents` 表的各自集合，跨空间索引单独建立。旧日志、密钥和照片沿用原表。照片上传仍走原分段加密存储。天空素材保留到房间清理且没有任何作品版本引用为止。
- 作品馆按小游戏、共创和共同世界筛选。主题从解密后的作品读取，筛选会继续查找后续页。需旧密钥的作品在「全部作品」中仍有占位。作品删除时移除版本和媒体关系，照片由剩余作品及房间的引用决定保留时长。
- 新存作品将封面配置写入加密作品内容。作品馆优先预览实际画格，其次预览作品引用的共同照片。进入视口后才渲染画格或解密照片。旧作品可从原加密内容生成预览，失效或未获授权的照片显示活动图案。
- 恢复同源库时，为快照中仍有效的作品同步最新头部和历史版本。已归档的活动照片沿这些作品的引用从参考库恢复，内容保持加密。参考库中删除、回收或失去引用的照片遵循现有删除状态。
- 旧密钥房间可按已持有的历史密钥回顾。创作内容、题目和答案在加密封装内。两位成员确认同一进度后可收藏共同作品。选取当前版本可以继续活动，适用于画布和长期世界。用户另行确认后，日记才新增入口。已删除或失效的引用显示占位，导出给出明文提示。
- 未完成房间持续保留。只有两人都在房间保留设置中确认，才开始计算 30 天闲置清理期限。每次提交进度会顺延，任一成员可取消清理。旧库未获确认的期限在启动时解除。两位成员确认结束后提示房间保留时间，已收藏作品继续按作品规则保存。

## 发布与回退

本地开发与同源隔离测试完成后，还需在两部真实手机和目标 HTTPS 站点上完成交互、触控、弱网、备份与恢复。M8 依赖通过既有公网放行项。只启用已验收的批次。

1. 新版启动前生成并校验旧库快照。保留上一发布包及独立的部署备份。
2. 在隔离候选库执行 v3 升级，验证开关、同步、密文照片、设备撤销和旧日记。
3. 如需停止新写入，清空 `US_WEB_PLAYGROUND` 并重启。使用支持 v3 的较早发布包时保持当前数据库。
4. 旧 v2 程序需要兼容的回退快照。候选库按现有恢复流程用最新同源库核对撤销与删除。保留新库和加密快照供再次升级时演练。业务写入已发生后，先核对版本与变更，避免用旧快照覆盖最后一批数据。

## 验收记录

2026-11-26 在隔离环境完成以下验证。使用两组合成账号、一次性 HTTPS 证书、独立浏览器上下文和临时 SQLite 库。

- `npm run check:web` 通过。覆盖 5000 条加密操作、两位成员确认检查点前后的重放、SQLite v2 升级与隔离恢复、撤销设备、删除作品及房间素材生命周期。
- 三组游乐园场景从双端入口走过 24 项，验证实时笔迹、框选、组合、搜索、房间继续时的共同收藏、作品 PNG、天空拼贴及日记关联。九关星际、十关光影迷宫、三间密室和两张厨房图的完整路线由领域测试复核。
- 双端重连用例重复通过两轮。每轮 100 笔分在 10 次断线中缓存并补发，每次恢复检查两端对象数和待同步队列，重开后比较全部 100 个物件的顺序和唯一性。
- `npm run test:play:perf` 通过。桌面 Chromium 的 1000 件、每件 20 个点的画布在绘制时没有重画静态笔迹。一次 110 个样本测得事件到 Canvas 绘图指令的 P95 为 0.5ms。该时间截止到绘图指令，手机落笔、屏幕呈现和云端同步延迟另行测量。带照片画布连续打开和关闭 20 次后，所有测试创建的 Object URL 均已释放。
- 端到端验证脚本还覆盖站点公开配置、旧站配对、共同与私人图文同步、离线冷启动和换机恢复。用 `US_WEB_TEST_PACKAGE` 指向待验收 ZIP 可测试解压后的应用。用 `US_PLAY_TEST_BROWSER=firefox` 或 `webkit` 可复跑游乐园用例，默认使用 Chromium。
- 隔离恢复用例运行发布包的 `backup-web.mjs` 和 `recover-web.mjs`。两位成员分别用自己的备份包重建密钥库，读取各自的私人作品以及同一共同作品的两版照片，复核已删除作品与被撤销设备均受限。覆盖作品馆筛选、小说 Markdown/JSON/PDF 和拼贴 PNG。
- C17 在默认局部视图绘制 10 × 10 格，旋转与视图切换沿用相同的物件 ID 和坐标。20 × 20 全图以色块显示物件分布，进入局部后再显示图标。在 390px 浏览器用 200 件合成物件核对局部视口、模拟触屏点击、全图和二维键盘操作。两位成员可主动领取观星装饰，已有基础物件与布局继续可用。
- C18 可从列表选中重叠的星点，再用触屏、鼠标或方向按钮移动。拖动时只绘制本机预览，抬手时提交并核对拖动前的坐标。打开原日记时保留当前房间或作品在背景中，关闭后延续原筛选、选中的星点和缩放。要归档的星座需要当前仍有权查看的至少三颗星。
- W24 每页至多显示 30 片叶子，树图与列表使用同一分页。年度 PNG 覆盖所选年份的全部可见叶子，私人叶子须本人开启并在导出时确认。作品馆的树只存所选共同回忆引用，新版支持 1000 条完整引用。旧作品以原版本的已保存引用呈现。
- G12 的镜头沿用当前地图，两端各自观看或跳过。剧情镜头不会提交房间操作。浏览器同一标签页刷新时依据本机观看记录和已同步的关卡进度恢复，双人进度仍由加密操作重放得出。开启系统或应用的减少动效选项，或在房间设置中降低动效时，可以直接操作地图。
- G12 在触屏或窄屏上提供单摇杆，方向按钮和地图键盘操作同时可用。纪念碑可引用整条共同日记或其中一张照片。照片移除后显示提示，仍有权访问的原日记可以打开。
- G12 在实时连接就绪时用相同的碰撞规则预览本机宇航员的一步移动。位置文字、压力板、星尘及对端显示均随已确认操作更新。共同累计 3、9、18 颗星尘时解锁三个宇航服装饰。两人可分别佩戴或卸下，星尘累计值沿用既有通关进度。
- G13 的两端同时显示反光镜、影之按钮和光桥的已确认状态。只允许影之角色走过影门。机关与传送操作记录发起位置，补发时仍核对同一关与位置。
- G04 的键盘与方向按钮使用同一移动节奏，单个成员每 180ms 至多发出一步。站点操作仍以当前交接位置、订单和手中食材核对。双浏览器测试从备菜走到装盘，并验证断线后交接只生效一次。
- G11 的两位成员分别查看本房间的机关与给搭档的线索。选择机关后可查看近景、当前状态和提示。通关后展示带两位成员显示名称的明信片，确认后可另存 PNG。
- C22 的目标日期和完成状态保存在原愿望记录，画布和愿望清单读取同一条记录。将已完成愿望写入共同日记需单独确认，生成的回忆使用当次完成日期。两位成员同时生成时可打开同一条回忆，已移到回收站的回忆可从原回收站恢复。
- W23 的触屏拖动从选中的家具开始。进入移动模式后，只有当前家具接管触屏拖动，空地保留页面滚动。鼠标与触屏拖动都按开始手势时的家具版本提交，对方在拖动期间完成的旋转或位置修改会触发冲突提示。
