# 第二阶段：上线准备与双人联调

用户已于 2026-10-30 确认首版功能性验收通过。首版发布包保留；本阶段沿用既有界面、记录格式、密钥和用户数据。

本阶段范围：

1. 检查云端依赖告警，验证官方 SDK 候选版本和兼容性，再决定候选构建使用的版本。
2. 加固请求校验、并发刷新与保存、锁定期间的异步响应以及本机写入失败处理。
3. 提供可重复执行的配置工具和部署前自检，区分本地构建通过、配置齐全、真实云端联调通过。
4. 补充只返回运行状态的连接检查接口，不读取或回传日记明文。
5. 生成 1.1.0 候选包、检查报告和真实双人验收步骤。

用户明确选择「先完成本地上线准备，暂未配置云环境」。因此 AppID 与环境 ID 保持占位 / 空值，未登录、创建云资源或部署。

## 本地候选版结果

- 新增「我的空间 → 连接与同步」，检查运行状态、最近成功刷新时间和可查看的记录数。`health` 不读取日记 / 照片，不回传用户和空间标识。
- 只读网络请求最多重试一次；保存、删除和 AI 生成不自动重发，超时或断网明确提示先刷新确认结果。
- 刷新期间新保存的记录不会被旧结果覆盖；锁定后返回的刷新 / 保存响应不能恢复界面缓存；本机数据库写入失败保留原内存状态。
- 配置工具只接收公开标识。自检分别输出本地准备与云配置状态，绑定当前测试、锁文件和构建产物；打包检查版本和产物哈希，生成 ZIP 及 SHA256。
- 云函数依赖候选为官方预发布 `wx-server-sdk 5.0.1-beta.1`，axios 同一 0.x 系列覆盖到 `0.34.0`。离线检查只覆盖 SDK 包装层；预发布状态和真实云端兼容性列为外部验收事项。

运行 `npm run release` 重现本地候选流程，实际检查时间、依赖审计和构建 SHA256 见 `release-readiness.json`。首版发布包继续保留，当前记录格式与 API 协议没有迁移。

## 下一步需要的条件

获得小程序 AppID 和 CloudBase 环境后，按 `DEPLOYMENT.md` 配置，在测试环境执行 `ACCEPTANCE.md`。云资源创建、真实 OpenID、模型服务、微信开发者工具及双手机测试的结果必须单独记录；本机检查不能替代。

本阶段不扩展语音视频、订阅提醒、家具摆放等功能；这些仍保留在后续功能迭代清单，等待下一次明确安排。
